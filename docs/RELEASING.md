# Releases and supply-chain security

How LabLink is built, released and verified, and the rules that keep that
process trustworthy.

## Dependencies

- Rust crates come only from crates.io (`deny.toml`: unknown registries and
  git sources are refused) and are locked by `Cargo.lock`; every build and
  test uses `--locked`.
- CI runs `cargo deny check` (advisories, licenses, bans, sources) and
  `cargo audit --deny warnings` on every change, with pinned tool versions.
  OSV-Scanner over `Cargo.lock` is a useful second opinion before a release.
- `THIRD_PARTY_LICENSES.md` is generated by `scripts/third-party.sh` and must
  match `Cargo.lock` (checked in CI and by `scripts/package.sh`).
- Dependabot proposes Cargo and GitHub Actions updates weekly; updates are
  reviewed like any other change.

## CI

- Workflow permissions default to `contents: read`; only the `provenance`
  job gets `id-token: write` and `attestations: write`. It runs only for
  `v*` tags and executes no repository code: it signs the artifacts the
  `release` job built and uploaded.
- Third-party actions are pinned by commit SHA; `actions/checkout` never
  persists the token. There is no `pull_request_target` workflow and no
  secret is used anywhere, so pull requests from forks cannot reach one.
- Every job has a timeout; superseded pull-request runs are cancelled.
- `secrets` scans the full Git history with gitleaks (`.gitleaks.toml`
  allowlists only the synthetic fixtures of the redaction tests).

## Building a release

`scripts/release.sh` builds the committed `HEAD` only (it refuses a dirty
tree):

1. Exports a clean `git archive` of `HEAD`.
2. Builds in `packaging/build.Dockerfile`: Ubuntu 20.04 pinned by digest
   (glibc 2.31 baseline), `rustup-init` pinned by version and SHA-256, the
   Rust toolchain from `rust-toolchain.toml`.
3. `scripts/package.sh` builds the `.deb` and the tarball with every
   timestamp set to the commit time (`SOURCE_DATE_EPOCH`), records the build
   in `BUILDINFO`, and writes `SHA256SUMS`.
4. `scripts/sbom.sh` adds a CycloneDX SBOM of `Cargo.lock`
   (`lablink-<version>.cdx.json`, deterministic) to `SHA256SUMS`.

Rebuilding the same commit gives byte-identical artifacts; to check:

```bash
scripts/release.sh && cp dist/SHA256SUMS /tmp/a
scripts/release.sh && diff /tmp/a dist/SHA256SUMS   # no output
```

In CI, a `v*` tag also gets a Sigstore build-provenance attestation for the
`.deb`, the tarball and the SBOM (`actions/attest-build-provenance`).

## Publishing

- Publish only what CI built for the tag (the `lablink-dist` artifact of
  that run), not files from a developer machine.
- Create the public repository from a fresh single-branch clone of the
  release branch, never by adding a public remote to a working repository
  with other history.
- Enable private vulnerability reporting, secret scanning with push
  protection, branch protection with required CI and review, before
  announcing.
- Date the CHANGELOG entry in the tagged commit.

## Verifying a download

```bash
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify lablink_<version>_amd64.deb --repo <owner>/<repo> \
    --signer-workflow <owner>/<repo>/.github/workflows/ci.yml \
    --source-ref refs/tags/v<version> --deny-self-hosted-runners
```

The attestation proves the file was built by this repository's CI workflow
from the tagged commit (`--source-ref` rejects attestations made for any other
ref). `lablink version` prints the version and commit; they
match the tag and `BUILDINFO`. The SBOM lists every crate compiled into the
binaries.

## Before every release

- [ ] `cargo test --workspace --locked`, clippy, fmt (CI green)
- [ ] `cargo deny check`, `cargo audit --deny warnings`, OSV-Scanner
- [ ] gitleaks over the full history
- [ ] `scripts/release.sh` twice, identical `SHA256SUMS`
- [ ] `scripts/cleanroom.sh` on ubuntu:20.04, 22.04 and 24.04 (includes the
      security steps: password isolation, other local user, package
      privileges, hostile import, security stop)
- [ ] CHANGELOG `Security` section lists fixed issues
